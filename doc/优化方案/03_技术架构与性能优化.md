# 技术架构与性能优化

> 设计方案，未实现；基线 dc18deb7eae6267abd8ccc5e7453c05e89ad1644；事实=静态代码证据，目标=拟定验收。
> 本文定义全套方案的会话、取消、分页、结果类型与 IPC 语义；数值均为待基准验证的初始预算。

## 1. 明确采用的架构

保留 React + Ant Design + Tauri + Rust/sqlx，不重写框架，不引入独立数据库代理服务。
把当前 [lib.rs](../../src-tauri/src/lib.rs) 的连接、解码、执行、AI、存储命令拆成单向依赖的领域层。
采用 Rust 状态中心 + 每会话 actor；actor 独占物理连接租约，串行执行 SQL、事务命令与清理。
React 使用按标签归一化的 Zustand 状态，IPC 调用集中封装，组件不得直接拼装带密码的 DBConfig。
应用级锁仅保护注册表元数据，不跨网络 await 持锁；同一会话 actor 串行，不同会话有限并发。
保留三驱动独立解码，不采用抹去所有类型的 Any 驱动作为核心，避免能力与精度进一步退化。

| 层次 | 推荐职责 | 不允许承担的职责 |
| --- | --- | --- |
| UI / workspace store | 草稿、标签、选区、结果窗口、作业可视状态 | 保存秘密、推断已提交、绕过授权 |
| IPC application | 参数校验、窗口所有权、版本校验、统一错误 | 直接把客户端 connectionId 当授权 |
| Session / Job actor | 固定租约、事务状态、背压、取消、终态去重 | 为同一事务另建连接 |
| Driver adapter | 方言、描述、绑定、流、取消能力、元数据 | 策略审批、UI 提示、持久化业务历史 |
| Repository / SecretStore | 原子配置、历史脱敏、凭据引用 | 自动连接、执行历史 SQL |
| Agent adapter | 获批上下文到服务、结构化建议 | 取得数据库执行句柄 |

规划新增：src/ipc/db.ts、src/stores/workspace.ts、src-tauri/src/db/mod.rs、src-tauri/src/db/session.rs、src-tauri/src/db/codec.rs、src-tauri/src/security.rs。
上述是后续改造位置，不是本次创建的源码文件；文件级任务见 [05](05_实施路线与任务拆解.md)。

## 2. 连接池与会话生命周期

当前 [run_dispatch](../../src-tauri/src/lib.rs#L422-L429) 每次建池，推荐改成 ConnectionManager 注册表。
池键为 connectionId + revision + accessProfile；只读/可写账户、TLS 与隧道修订不共享错误身份的池。
网络库每个配置默认最多 4 条数据连接，另保留 1 条按需控制连接；全应用默认 16 条含控制连接。
SQLite 每文件默认最多 2 个读取会话、1 个写入租约；写入调度串行，不能把“文件库”当无限并发内存库。
连接数上限同时约束元数据任务、查询、导出与控制通道，避免取消请求被业务池占满。
保留现有 15 秒建连、10 秒获取超时作为迁移初值；新增交互查询默认 30 秒 deadline、锁等待预算 5 秒。
只读长导出可经确认延长 deadline；写入超时不自动重放。时间策略须映射各驱动能力，不能只包 timeout Future。

生命周期：配置保存不连接 → 首次操作建池 → 打开标签创建逻辑会话 → 首次查询取得租约 → 清理/关闭后归还。
同一标签有租约期间，所有 SQL、SET、临时对象和 BEGIN/COMMIT 均在同一物理连接上。
空闲 5 分钟且无事务/临时状态时可回收租约；回收使 session generation 递增，并明确提示“新数据库会话”。
不能透明回收用户声明的临时表/会话变量状态；无法证明已复位的连接直接关闭，不返回共享池。
编辑配置会使旧 revision 进入 retiring：不接新作业，已有事务由用户结束；绝不热替换连接。
断开：停止接单 → 请求取消活动作业 → 回滚未提交事务 → 清理连接 → 关闭池；返回分阶段状态。
异常关闭依赖数据库断线处理未提交事务，但提交响应丢失依旧 unknown，不因断线宣称回滚成功。

## 3. 查询会话和状态模型

| 模型 | 必需字段与规则 |
| --- | --- |
| ConnectionProfileV2 | id、revision、driver、environment、endpoint、database、username、secretRef、tls、tunnelRef；不含明文秘密 |
| DbObjectRef | connectionId、revision、catalog、schema、name、kind；名称保留原始大小写 |
| QuerySession | sessionId、ownerWindow、tabId、connectionId、revision、generation、schema、accessMode、transactionState |
| QueryJob | queryId、requestId、sessionId、generation、source、sqlDigest、deadline、state、nextSeq、resultIds |
| TransactionState | idle、active、failed、committing、committed、rollingBack、rolledBack、unknown |
| QueryState | queued、running、streaming、cancelRequested、succeeded、failed、cancelled、unknown |
| ResultDescriptor | resultId、statementIndex、columns、complete、truncated、fetchedRows、affectedRows、timings |

environment 的完整集合为 unknown/dev/test/staging/prod/custom；旧记录默认 unknown 和 readOnly。
connection revision 是持久化 CAS 版本；session generation 是数据库连接更换代次，两者不能混用。
SQL 文本快照保留在作业内存中以执行；历史和日志只存脱敏模板/摘要，不把完整 SQL 当遥测维度。
同一 requestId 的相同请求返回已有 queryId；请求体摘要不同时拒绝，而不是覆盖原作业。
去重仅在本次应用进程及指定保留期内有效，不能据此宣称断网写入 exactly-once。
关闭标签后返回的批次不得写入新标签；UI 校验 tabId/sessionId/generation/queryId 四元组。

## 4. 版本化 IPC 契约（拟定 v2）

命令采用 snake_case，JSON 字段统一 camelCase；由 Rust DTO 导出类型/契约夹具，替换当前 invoke any。
任何 open/query/transaction 命令只接受后端登记的连接引用，绝不接受客户端任意替换完整网络配置执行。
连接创建/更新是单独的受限命令，需校验 endpoint、驱动能力、秘密保存授权和 revision。

| 命令 | 请求核心 | 响应/边界 |
| --- | --- | --- |
| connection_open_v2 | apiVersion、connectionId、revision、tabId、accessMode | sessionId、generation、capabilities、公开安全状态 |
| query_start_v2 | requestId、sessionId、generation、sql、parameters、source、approvalId、limits | queryId、state；不返回全量结果 |
| query_next_v2 | queryId、expectedSeq、ackSeq | 同序号可重取的 Batch 或 pending/terminal |
| query_status_v2 | queryId | 权威终态、事务状态、取消结果和脱敏错误 |
| query_cancel_v2 | queryId、reason | accepted、cancelState；accepted 不代表已经停止 |
| session_close_v2 | sessionId、generation、rollbackApproved | closing/closed/unknown；事务未授权结束时拒绝 |
| transaction_action_v2 | sessionId、generation、action、approvalId | 新事务状态；只在原 actor 上执行 |
| metadata_list_v2 | sessionId、objectRef、kind、cursor | 结构化对象与缓存版本，不跨 schema 猜测 |
| agent_assist_v2 | intent、sessionContextRef、resultId、approvedSampleRef | suggestionId、内容、SQL 草稿、来源，不含执行权 |

示例：查询响应是描述性的协议样例，标识均为虚构，不是实际运行结果。

```json
{
  "apiVersion": 2,
  "queryId": "demo-query",
  "sessionId": "demo-session",
  "generation": 1,
  "seq": 0,
  "resultId": "demo-result",
  "columns": [
    {"ordinal": 0, "name": "id", "nativeType": "int8", "logicalType": "integer", "nullable": false},
    {"ordinal": 1, "name": "payload", "nativeType": "bytea", "logicalType": "binary", "nullable": true}
  ],
  "rows": [[{"kind": "integer", "value": "9007199254740993"}, {"kind": "null"}]],
  "complete": false,
  "truncated": false,
  "affectedRows": null
}
```

Batch 首包或新 resultId 必有 columns；后续包带 descriptorVersion，列定义不可无通知改变。
query_next_v2 每作业最多一个未确认批次；相同 expectedSeq 重试返回同包，ack 后才释放，不因 IPC 重试多执行 SQL。
pending 不推进序号；终态单独保存，已关闭/过期结果返回明确 RESULT_EXPIRED，不自动重执行补数据。
所有错误结构：code、stage、retryable、queryId、transactionState、safeMessage；不得直接透传带敏感字面量的原始错误。
脚本首期只接受可解析、受支持的语句序列；未知多结果协议拒绝执行，不能静默只显示最后一个结果。

## 5. 结果类型与无损边界

当前 [三驱动解码](../../src-tauri/src/lib.rs#L245-L349) 具有基本分支，推荐逐项扩充而非退回“全转字符串”。
列元数据来自驱动 describe/prepare 或结果协议描述；零行仍有列，不使用首行构造 schema。
描述与实际执行须同一会话并使用相同参数类型；准备阶段不能为获类型额外执行有副作用语句。
当驱动不能安全描述某类语句时返回 capability 限制，不能偷偷先跑一次。

| 数据族 | IPC 表示 | 显示/回写规则 |
| --- | --- | --- |
| SQL NULL | kind=null，无 value | 与空字符串、JSON null、失败完全区分 |
| 整数含 u64 | kind=integer，十进制字符串 | JS 可用 BigInt 比较，不经 Number；JSON 导出仍用字符串 |
| DECIMAL/NUMERIC | kind=decimal，原值字符串、precision/scale | 不转 float；超 rust_decimal 范围改用驱动专用无损路径 |
| 浮点 | kind=float，有限值或 NaN/Infinity 标签 | 不把非有限值序列化成 null；标注浮点精度 |
| 字符串 | kind=text，UTF-8 文本、原长度 | 长度限制只影响预览，复制全文需显式读取 |
| 二进制 | kind=binary，base64/byteLength 或 cellRef | 任意字节往返一致，不用 from_utf8_lossy |
| 日期/无时区时间 | date/localTime/localDateTime，原文本 | 禁止浏览器 Date 自动推断本地时区 |
| 带时区时间 | instant，UTC 文本与展示时区 | PG 不保留原输入时区名；MySQL 记录会话时区而非伪造来源时区 |
| MySQL TIME | duration，带符号文本 | 能覆盖负数和超 24 小时，不能只用 NaiveTime |
| JSON/JSONB | kind=json，文本 + 按需树预览 | 避免 JS parse 丢大数；SQL NULL 与文档 null 区分 |
| UUID / enum / array | 对应标签 + 原生类型与规范文本 | 数组保维度/null 元素；无适配器不冒充普通字符串 |
| 未支持或解码失败 | unsupported/decodeError + nativeType | 禁止编辑；提示类型，不伪装 SQL NULL |

PG numeric、数组/范围、域类型、MySQL BIT/YEAR/零日期等先补夹具再开放编辑；本方案不声称已有完整支持。
大单元格默认仅 64 KiB 预览；单值 16 MiB 交互上限，超限返回 VALUE_TOO_LARGE 或专用导出提示。
cellRef 仅引用尚在后端受限缓存中的数据，不能依据已结束查询重查原表冒充同一值。
驱动可能在吐出一行前缓冲整行/网络包，因此这些上限不是任意恶意大字段下的绝对内存保证；需驱动级负载测试。

## 6. 分页、流式与 10 万行策略

明确分成两条路径，不使用“追加 LIMIT 后仍 fetch_all”冒充通用分页。
**自由 SQL**：执行一次，以 sqlx 行流逐批解码，前端拉取产生背压；不随意改写聚合、CTE、窗口函数或 LIMIT。
流式查询仍可能在数据库端完成昂贵计算或排序；客户端背压只约束传输/应用缓存，不保证服务端计算提前停止。
默认交互最多读取 10000 行，达到阈值暂停并提示；用户明确扩展预算到 100000 行或选择独立完整导出。
暂停最多 60 秒，超时请求取消并释放资源；达到预览预算的结果标 truncated，不能标 complete。
作业消费完成后释放流；若因预算提前停止，必须确认协议清理/取消，再决定连接是否可复用。
**表数据浏览**：明确唯一键和稳定 ORDER BY，通过结构化查询使用 keyset，每次最多 pageSize+1 行。
复合键生成词典序谓词并绑定值；排序键可空时定义 NULL 顺序；最终补唯一键，不能按非唯一列漏行。
pageSize 默认 200、最大 500；客户端只接这一页；不要先全量查询再取 slice。
无唯一键时只允许带警告的受限预览；不承诺无重漏，不开放编辑，不默认深 OFFSET 扫描。
默认翻页为各语句时点数据，不声称稳定快照；要求一致快照时建立只读事务并设置最长 60 秒租期。
刷新/排序/过滤生成新结果版本；已有变更集必须先处理，不可跨结果版本提交编辑。

### 内存、背压与展示预算

- 基准为 100000 行、20 列、平均每行约 256 B 的合成数据，不含极端 LOB，详见 [06](06_测试验收与风险清单.md)。
- 每批最多 500 行且序列化大小最多 1 MiB，先到任一上限即切批；大单元格走引用，不突破批次限额。
- 后端生产队列最多 2 批，加 1 批待确认；单作业数据缓存总预算 16 MiB，达到上限停止生产。
- 前端最多 2000 行缓存且总数据预算 16 MiB，虚拟渲染不超过 200 行；淘汰旧批次后明确不可离线任意回翻。
- 如用户需要 10 万行任意随机回看，S2 不假装支持，建议完整导出；后续评估加密临时索引缓存。
- 只读导出在 Rust 写文件，WebView 只接进度；导出从新只读作业开始，必须告知快照与当前结果不同。
- F1 基准目标：热连接首批 p95 不超过 1 秒，额外 RSS 不超过 200 MiB，UI 交互 p95 不超过 100 ms。
- 记录 Rust 与 WebView 内存，不只看 JS 堆；慢 SQL 的服务端执行时间不计入“客户端吞吐优化”成果。

## 7. 取消不等于 kill

当前无取消命令；现有连接超时不能中止任意已提交 SQL，见 [连接辅助](../../src-tauri/src/lib.rs#L164-L220)。
取消首先置 cancelRequested，停止发新批次，并在会话 actor 上请求驱动取消；终态要以数据库/协议完成为依据。

| 驱动 | 推荐停止路径 | 必须验证的条件 |
| --- | --- | --- |
| PostgreSQL | 后端持有本次租约的 backend pid；受限控制连接调用 pg_cancel_backend | 权限与目标身份、取消竞态、事务 aborted 状态；不默认 pg_terminate_backend |
| MySQL | 后端记录租约 connection ID；控制连接执行 KILL QUERY | 仅当前归属会话、最小权限；不默认 KILL CONNECTION，不把已提交写入当已回滚 |
| SQLite | 使用与本租约绑定的 interrupt 能力 | sqlx 0.8 实际可用接口/句柄线程安全须验证；若不可安全集成则返回 unsupported，不捏造 API |

控制 ID 不能来自前端；取消终结前不能让目标连接执行下一个作业，防止迟到的取消打断新查询。
仅 drop Future 或断开 IPC 是“停止等待”，不证明服务端已停；不得立刻把连接归还池。
取消请求 2 秒未确认则展示 pending，达到清理预算转 unknown 并隔离租约，不伪报 cancelled。
取消后 PG 失败事务应显式 rollback；MySQL 与 SQLite 同样检查事务状态，再决定归还或销毁连接。
查询自然完成与取消并发时，数据库已完成则如实显示 succeeded/committed，不强行改写历史为取消成功。
强制终止物理会话属于独立高风险管理动作，首期不开放自动升级；取消无法保证撤销已提交数据。

## 8. 驱动抽象与并发一致性

DriverCapabilities 明确描述 readOnly、cancelQuery、describe、returning、transactionalDdl、explain、stream、binaryCodec 等能力。
每个能力允许 supported/unsupported/unverified；unverified 在发布能力表中不可显示为可用。
SQL 返回行还是影响行数应来自协议/驱动执行结果，不继续依赖 is_query_stmt 前缀来决定安全或忽略 RETURNING。
跨驱动公共层只负责作业生命周期、授权与 ResultDescriptor，方言引用和类型处理留在适配器。
查询作业与元数据缓存分开；缓存键必须含连接 revision、catalog、schema、对象和元数据版本。
同一对象重复加载可合并在途请求；连接切换立即使旧请求 generation 失效，不污染当前树。
每会话一次一个查询/事务操作；结果流尚未结束时拒绝同连接执行另一个命令，避免协议相互消费。
事务内生成的临时对象/SET 状态不可放进全局 schema 缓存，更不能提供给其他连接的 Agent。
requestId、queryId、resultId 使用随机 UUID；历史终态去重，日志使用低敏 ID 串联阶段计时。

## 9. 兼容策略与性能门禁

S0 先在现有返回模型上修列名与危险入口；S1 引入 v2，旧接口必须走同一安全门禁，不保留绕过路径。
数据库驱动版本在后续实现开始时与用户原有锁文件协调；本次不读取/调整锁文件，也不宣称重现构建。
把单体拆分与行为修复分开验证：先契约夹具，再三驱动隔离回归，最后 UI 与性能。
架构验收 A01–A07、A15、A17、A19，取消能力未验证的驱动不开放相应完成承诺。
不以行数分页 UI、设置 LIMIT、缩小 WebView 表格高度或增加池连接数代替完整资源治理。
