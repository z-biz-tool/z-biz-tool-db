## 3. P0：数据真实性与执行安全

### DB-01 结果契约没有贯穿 UI｜已确认｜P0
- 证据：[Rust 结果模型 26–33](../../src-tauri/src/lib.rs#L26-L33)、[UI 接收 198–202](../../src/App.tsx#L198-L202)、[列生成 680–688](../../src/App.tsx#L680-L688)。
- Rust 的 rows 是二维数组，列名在 columns；UI 丢弃 columns，对数组调用 Object.keys 得到序号，而非数据库列名。
- 另外三驱动从首行取列定义，零行时列名也丢失；[执行器 355–418](../../src-tauri/src/lib.rs#L355-L418) 支持此结论。
- 建议：统一版本化结果模型，以 ordinal 作为列身份；零行结果仍返回描述信息，DML 显示 affectedRows。
- 验收关联 A01、A02；先修契约，再做复制、导出和编辑。

### DB-02 NULL 与失败混淆，二进制有损｜已确认｜P0
- 证据：[解码辅助 245–269](../../src-tauri/src/lib.rs#L245-L269)、[三驱动解码 271–349](../../src-tauri/src/lib.rs#L271-L349)。
- try_get 错误和空值都可落入 None，最终变成 JSON null；二进制使用 from_utf8_lossy，无法无损还原任意字节。
- 这不是“所有类型都错误”，而是未覆盖/异常值无法与 SQL NULL 区分，后续导出会放大失真。
- 建议：显式 null、binary、unsupported、decode_error 标签；失败要保留原生类型与安全错误码。
- 验收关联 A02、A03；不把显示替代字符当作原始二进制值。

### DB-03 大整数、数值范围及时区缺少跨 IPC 契约｜已确认 + 假设｜P0
- 证据：[MySQL 287–293](../../src-tauri/src/lib.rs#L287-L293)、[PG 318–328](../../src-tauri/src/lib.rs#L318-L328)、[SQLite 343–345](../../src-tauri/src/lib.rs#L343-L345)。
- i64/u64 序列化为 JSON 数字，前端没有精度保护；超过 JS 安全整数范围的值存在舍入风险。
- 已有 Decimal、chrono、UUID、JSON 解码；不能说这些完全不支持，但 Decimal 范围外数值、PG 扩展类型、MySQL TIME 范围仍需夹具验证。
- 建议：大整数和十进制定点数用字符串；时区与无时区值分型，不宣称 MySQL TIMESTAMP 的原始时区被保留。
- 验收关联 A02、A03；运行时类型名称与序列化细节仍待版本固定后的测试。

### DB-04 Agent 结果分析会隐式重新执行 SQL｜已确认｜P0
- 证据：[agent_results_analyze 603–625](../../src-tauri/src/lib.rs#L603-L625)、[命令注册 1091–1094](../../src-tauri/src/lib.rs#L1091-L1094)。
- 该命令先调用通用执行，再把完整 rows 交给本地 HTTP 服务；没有只读校验、复用结果或逐次数据授权。
- 触发条件是调用已注册命令；主 UI 当前未走此路径，不能写成“每次点击分析都会重执行”。
- 建议：移除分析的 SQL 执行能力，仅接 resultId 与获批抽样；默认不允许自动执行破坏性 SQL。
- 验收关联 A08、A09；本地服务也不能天然视为可信方。

### DB-05 AI 路径割裂并把示例当成功｜已确认｜P0 止误导 / P1 接通
- 证据：[AgentManager 36–81](../../src/agent/AgentManager.ts#L36-L81)、[App 336–439](../../src/App.tsx#L336-L439)、[配置入口 797–807](../../src/App.tsx#L797-L807)。
- 自然语言被插入固定 users 查询，优化仅大写；主 UI 调的是此 store，不是 Rust AI 命令。
- 解释 SQL 实际调 optimize；结果弹窗仅在其内部动作成功后打开，外部可见按钮只打开配置，存在入口不可达的静态路径问题。
- Rust HTTP 能力确实存在，但请求协议兼容性与服务可用性未验证，不能说“没有 AI 代码”或“AI 已可用”。
- 建议：先标不可用并停用假成功，再统一适配器、配置状态、入口和建议 diff；验收 A08、A20。

### DB-06 通用执行缺少后端授权策略｜已确认｜P0
- 证据：[execute_query 757–775](../../src-tauri/src/lib.rs#L757-L775)、[语句分类 232–241](../../src-tauri/src/lib.rs#L232-L241)、[执行按钮 903–920](../../src/App.tsx#L903-L920)。
- 只检查 SQL 非空；前缀判断用于选择结果读取方式，不是只读安全策略，也没有生产环境确认。
- 注释前缀、写入 CTE、RETURNING、存储过程及多语句的处理不能由 starts_with 推断安全性或结果形态。
- 建议：数据库最小权限 + 后端策略 + 方言解析风险提示；未知语句默认拒绝只读通道，写入另行授权。
- 验收关联 A06、A07；只读模式不能仅靠字符串过滤。

### DB-07 批量执行没有事务/会话保证｜已确认｜P0
- 证据：[execute_batch 943–968](../../src-tauri/src/lib.rs#L943-L968)、[run_dispatch 422–429](../../src-tauri/src/lib.rs#L422-L429)。
- 每条语句单独创建池；中间失败直接返回错误，没有整体回滚或已完成项的结构化报告。
- 因此 BEGIN、DML、COMMIT 不能依赖此接口跨调用绑定同一物理连接；前面成功写入可能已提交。
- 建议：S0 封堵“原子批量”误用，S1 建会话执行器，S3 再交付事务编辑和导入；不跨连接重试提交。
- 验收关联 A05、A07、A14。

### DB-08 连接与 AI 秘密随配置明文序列化｜已确认｜P0
- 证据：[ConnectionRecord 114–133](../../src-tauri/src/lib.rs#L114-L133)、[保存连接 96–99](../../src-tauri/src/queries.rs#L96-L99)、[AI 配置 435–469](../../src-tauri/src/lib.rs#L435-L469)。
- 类型含秘密字段，JSON 写入没有秘密分离；加载命令也把秘密返回前端。此判断不需要读取任何实际配置值。
- 配置导出明确排除了密码，见 [App 583–609](../../src/App.tsx#L583-L609)，不应把无密码导出列为漏洞。
- 建议：macOS Keychain，其他平台凭据库；不可用时仅内存，不回退明文；迁移不新建明文备份。
- 验收关联 A10、A11。

### DB-09 整文件覆盖与静默失败使持久化不可靠｜已确认 + 假设｜P0
- 证据：[queries.rs 40–109](../../src-tauri/src/queries.rs#L40-L109)、[UI 294–319](../../src/App.tsx#L294-L319)、[保存 538–559](../../src/App.tsx#L538-L559)。
- 文件直接 write，收藏先读后改；没有版本/CAS、原子替换或写入协调。并发丢更新与中断损坏为待故障注入验证的风险。
- UI 未等待保存完成即提示成功；启动加载异常被吞掉，可能把损坏误看作空列表，随后写入覆盖。
- 建议：单写者、revision、临时文件同步后替换；加载失败进入恢复态，不能自动保存空配置。
- 验收关联 A11、A12、A13。

### DB-10 连接池按请求创建，断开不管理资源｜已确认｜P0 语义 / P1 性能
- 证据：[池创建 169–220](../../src-tauri/src/lib.rs#L169-L220)、[分发 422–429](../../src-tauri/src/lib.rs#L422-L429)、[UI 529–535](../../src/App.tsx#L529-L535)。
- 测试连接、查表、查列、执行 SQL 均可创建独立池；未见应用级池注册表和显式 disconnect 命令。
- UI 断开不能代表后台查询已停止；不能据此断言 sqlx Drop 永久泄漏连接。
- 建议：连接修订作为池键、查询会话独占租约、断开请求与完成状态分离；验收 A04、A05。

### DB-11 标签与异步响应缺少身份隔离｜已确认 + 假设｜P0
- 证据：[全局状态 110–128](../../src/App.tsx#L110-L128)、[连接回写 458–496](../../src/App.tsx#L458-L496)、[切页 611–643](../../src/App.tsx#L611-L643)。
- 查询、表、列结果是全局状态，tabs 仅存 SQL；回写未校验请求所属连接、标签或修订。
- 慢 A 请求覆盖快 B、切库后出现旧结果是可推导竞态，未在 UI 运行复现。
- 新增标签前未同步当前草稿，也存在草稿丢失风险；删除/编辑连接未同步失效全部会话。
- 建议：会话和请求 generation 校验、每标签独立结果与即时草稿保存；验收 A04、A18。

### DB-12 PostgreSQL schema 身份被丢弃｜已确认｜P0 防误定位 / P1 导航
- 证据：[PG 表列表 810–832](../../src-tauri/src/lib.rs#L810-L832)、[UI 表键 847–860](../../src/App.tsx#L847-L860)、[结构过滤 888–902](../../src-tauri/src/lib.rs#L888-L902)。
- 后端返回多 schema 的表；UI key 和选择参数只有表名；查列固定 current_schema()。
- 同名表可能冲突、非默认 schema 结构不能准确寻址；这是明确契约缺口，不是 PG 未接入。
- 建议：使用 catalog/schema/name 对象引用，全限定标识符由驱动正确引用；验收 A15。

### DB-13 正则格式化可改动字面量与注释｜已确认｜P0
- 证据：[Rust 格式化 970–992](../../src-tauri/src/lib.rs#L970-L992)、[UI 降级 249–271](../../src/App.tsx#L249-L271)。
- 两端均无词法边界地替换关键字，字符串中的 from/where 等也可能被换行或改写；不是单纯排版差异。
- 建议：统一方言词法感知格式化，保留字面量、注释、参数；解析失败保持原文，不静默正则降级。
- 验收关联 A16；格式化始终支持撤销且不自动执行。
