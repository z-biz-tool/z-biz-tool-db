## 1. 测试策略与环境

### 1.1 测试金字塔

| 层级 | 范围 | 工具/框架 | 数据源 | 执行时机 |
| --- | --- | --- | --- | --- |
| 单元 | Rust 解码/分类/持久化逻辑；TS 状态/IPC 类型 | cargo test；vitest | 内存构造 | 每次 commit |
| 集成 | Rust 命令 → 数据库；前端 → Tauri invoke | cargo test + Docker Compose | 临时容器实例 | PR 合入 |
| 端到端 | 完整用户流程（连接→查询→导出） | Tauri driver + Playwright/WebDriver | 临时容器 | 阶段门禁 |
| 故障注入 | 网络断开、文件损坏、并发竞态、超时 | toxiproxy + 自定义中间件 | 临时容器 | S1 起每阶段 |
| 安全 | 秘密隔离、权限收敛、注入防护 | cargo audit + 手动渗透 + 自动化扫描 | 专用夹具 | S0/S1/S3 |
| 性能基准 | 10 万行流式、连接池复用、UI 响应 | criterion + 自定义 bench + Lighthouse | 合成数据集 | S2 起 |

### 1.2 测试环境隔离原则

- **数据库**：Docker Compose 启动临时 MySQL 8.0/PostgreSQL 16/SQLite 文件实例，端口随机映射，测试完成后 `docker compose down -v` 销毁。
- **文件系统**：所有持久化测试使用 `tempfile::TempDir`（Rust）或 `mkdtemp`（脚本）；通过 `Z_BIZ_TOOL_DB_DATA_DIR` 环境变量注入。
- **网络**：集成测试禁止访问外网；AI/Agent HTTP 测试使用 mock server（wiremock）。
- **秘密**：测试夹具使用固定假密码 `test_password_do_not_use`；Keychain 测试使用专用测试服务名（`com.zifang.z-biz-tool-db.test`）。
- **不碰生产数据**：任何测试不得连接非临时容器的数据库；CI secrets 不含真实数据库凭据。
- **进程隔离**：落盘测试不修改全局环境变量后不恢复；使用子进程或 `#[should_panic]` 隔离。

## 4. 故障注入场景

| 场景 ID | 注入点 | 方法 | 预期行为 | 验收关联 |
| --- | --- | --- | --- | --- |
| FI-01 | 数据库网络中断（查询中） | toxiproxy 切断 MySQL/PG 代理 | 查询转 failed/unknown；事务未提交转 unknown；连接隔离 | A05、A14 |
| FI-02 | 数据库网络中断（COMMIT 后） | toxiproxy 在 COMMIT 响应前切断 | 事务状态 unknown；不自动重试 COMMIT | A14 |
| FI-03 | 文件写入中断 | 在 rename 前 kill 进程 | 文件为完整旧版；恢复态可用 | A11 |
| FI-04 | 配置文件损坏 | 手动截断 JSON | 加载进入恢复态；不静默清空后覆盖 | A12 |
| FI-05 | 并发写入竞争 | 两个 tokio task 同时 save_connections | revision CAS 拒绝后者；不丢更新 | A13 |
| FI-06 | Keychain 不可用 | 模拟 security-framework 返回错误 | 降级为仅内存模式；不写入明文 | A10 |
| FI-07 | 查询超时 | toxiproxy 增加 60s 延迟 | 30s deadline 触发取消；连接清理后可复用 | A04 |
| FI-08 | 大结果 OOM 边界 | DS-04 含 1 MiB 单元格 | 批次大小限制生效；VALUE_TOO_LARGE 返回而非 OOM | A17 |
| FI-09 | Agent 服务不可达 | mock server 关闭 | 返回明确"服务不可用"错误；不返回示例 SQL | A20 |
| FI-10 | 审批 token 过期/重放 | 时间推进 + 重放请求 | 过期拒绝；已消费拒绝；SQL 变更后拒绝 | A07 |

## 6. 性能验收基准

### 6.1 基准环境

- 硬件：Apple M1 16GB / Intel i7 32GB（CI 使用 GitHub Actions runner）
- 数据库：Docker 本地容器，同机网络（延迟 < 1ms）
- 数据集：DS-03（100000 行 × 20 列，每行约 256 B，总约 25 MB）
- 测量工具：criterion（Rust）、Performance API（前端）、/usr/bin/time（RSS）

### 6.2 基准指标

| 指标 ID | 场景 | 目标值 | 测量方法 | 假设 |
| --- | --- | --- | --- | --- |
| P-01 | 首批 500 行到达时间 | p95 ≤ 1s | Rust Instant 从 query_start 到首批序列化完成 | 热连接（池已有空闲连接） |
| P-02 | 完整 10 万行流式读取 | 总时间 ≤ 30s | 从 query_start 到所有批次 ack | 无网络抖动 |
| P-03 | Rust 进程 RSS 增量 | ≤ 200 MiB | 流式读取过程中峰值 RSS - 基线 RSS | 不含数据库进程 |
| P-04 | WebView RSS 增量 | ≤ 150 MiB | 虚拟滚动缓存 2000 行时 | Chrome DevTools Protocol |
| P-05 | UI 交互响应 | p95 ≤ 100 ms | 滚动/切标签/点击到帧渲染完成 | requestAnimationFrame 测量 |
| P-06 | 连接池复用 | 第 2 次查询无建连开销 | 比较首次（含建连）与后续耗时差 | 差值 ≥ 100ms 证明复用有效 |
| P-07 | 10 万行 CSV 导出 | ≤ 60s，文件完整可解析 | Rust 写文件完成时间 + wc -l 验证 | 写入本地 SSD |
| P-08 | Keyset 翻页 | 每页 ≤ 500ms | 从请求到响应（pageSize=200） | 有唯一索引 |
| P-09 | 取消响应 | ≤ 2s 展示状态变化 | 从 cancel 请求到 UI 状态更新 | PG/MySQL |
| P-10 | 应用冷启动 | ≤ 3s 到可交互 | 从进程启动到首屏渲染完成 | 无连接自动恢复 |

### 6.3 性能退化预警

任何 PR 合入后若 P-01 ~ P-05 退化超过 20%，CI 标记为 performance regression 并阻断。
基准每阶段门禁时完整运行一次；日常 CI 仅运行 P-01、P-05、P-06 快速子集。

## 8. 测试执行规则

### 8.1 通过标准

- **未经测试不得声称通过**：任何验收项（A01–A24）必须有对应自动化测试或经 Q 签字的手动测试记录。
- 静态代码审阅仅作为"已确认缺陷"证据，不作为"通过"证据。
- 性能指标必须在基准环境下至少运行 3 次取 p95；单次结果不作为最终判定。
- 安全测试项由 S 角色独立复核；R/F 不可自审自签。

### 8.2 跳过与降级

- 网络库测试（MySQL/PG）在本地无 Docker 时可 `#[ignore]` 跳过，但 CI 必须运行。
- Keychain 测试在 Linux CI 上使用 mock；macOS 手动验证至少一次。
- SSH 隧道测试在 S3 评估完成前标记为 blocked。

### 8.3 回归策略

- 每个 bug fix 必须附带回归测试；测试先于修复编写（红灯 → 绿灯）。
- 阶段门禁通过后的代码变更需重新运行该阶段全部验收项。
- 性能基准每阶段完整运行；日常 PR 运行快速子集。

### 8.4 测试数据清理

- Docker 容器测试后 `down -v` 销毁卷。
- 临时目录使用 RAII guard（TempDir）自动清理。
- CI 工件保留 7 天后自动过期。
- 不在测试中创建持久化数据到用户真实 DATA_DIR。
