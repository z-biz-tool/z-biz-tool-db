## 3. DB 独特价值

DB 的价值不是再做一个通用聊天窗口，而是让用户明确知道：正在对哪个环境、哪个 schema、哪条连接会话执行哪一段 SQL。
相比其他工具项目，DB 的错误会直接影响业务记录、事务状态和数据泄露边界，正确性应高于功能数量。

推荐定位：**本地优先、结果保真、环境可辨、写入可控的三驱动数据库工作台**。
第一阶段聚焦 MySQL、PostgreSQL、SQLite；不把 UI 里的 SQL Server 选项视为驱动已经实现。
网络数据库用于授权后的开发与排障；SQLite 用于用户明确选择的本地文件，不扫描用户磁盘。
产品可借鉴 DBeaver/DataGrip 的环境标记、查询上下文和事务可见性理念，不依赖未经核验的竞品版本事实。

## 5. 优先级规则

- P0：存在错误执行、数据失真、秘密泄露或不可恢复状态风险；阻止新写入/Agent 自动化推广。
- P1：完成可信专业查询工作流，提升可控性、恢复性与性能；必须在 P0 门禁后扩展。
- P2：基于稳定内核提升分析效率，不替代安全基础设施。
- 优先级是业务排序；阶段是实施顺序。P0 可先通过禁用危险入口止血，再做结构性修复。

## 6. 首要架构决策

采用 Rust 统一管理连接池、会话、事务、查询作业和授权；React 只持公开连接配置及可撤销的操作句柄。
标签页绑定查询会话；事务绑定同一物理连接，连接池复用不等于事务连续性。
结果使用有类型的列元数据与按列序号存储的单元格，不把数据库大整数强制转 JavaScript Number。
交互查询采用有背压的批次读取，表浏览采用稳定排序的服务端 keyset；不得 fetch_all 后切片冒充分页。
取消表示请求停止；只有数据库确认且连接清理完成才能标记已取消，绝不默认升级为 kill 会话。
写入、批量、导入、执行计划 ANALYZE 和 Agent 建议共用后端授权策略，不依赖 SQL 前缀或 UI 禁用。

## 7. 成功与非目标

成功标准是：结果真实、上下文准确、敏感数据留在授权边界内、操作可解释、失败可恢复。
量化验收编号统一为 A01–A24，数据集与设备假设统一见 [06 验收](06_测试验收与风险清单.md)。
不做在线教育、CPU 课程、数据库服务托管或通用插件市场；不扩展未经验证的新驱动。
不把索引建议自动转换为 DDL，不让 Agent 获得无人确认的破坏性 SQL 执行权。
本次无安装、构建、启动、数据库连接、提交或推送；所有测试和性能指标均为后续拟定验收。
